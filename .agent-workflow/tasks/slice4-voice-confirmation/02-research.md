# Slice 4 research — voice confirmation outside grants

Date: 2026-10-05. Scope: Solana devnet transfers that are not covered by an active delegated grant. The current branch includes Slice 3 at `26a8098`.

## Findings from source

- Realtime voice tools are strict and address-free: `send_token` accepts amount plus versioned `recipientId` and rejects unknown keys; `confirm_transfer` and `cancel_transfer` accept no arguments. See `src/livekit/realtime-tools/create-realtime-tools.ts` (`sendTokenSchema`, `confirmationSchema`, `cancelSchema`).
- `send_token` calls `WalletConversationService.previewTransfer`; that service reloads the user-owned conversation and versioned recipient, applies live policy, asks the wallet provider for a preview, persists the pending transfer, and publishes a revision. The preview message includes the saved recipient name but not its estimated fee. The model-facing mapper currently omits both recipient and fee from structured fields. See `src/conversations/service.ts` (`previewTransfer`) and `src/livekit/realtime-tools/create-realtime-tools.ts` (`toVoiceToolResult`).
- `confirm_transfer` reads the current persisted pending preview and calls `resolveDecision(confirm)`; `cancel_transfer` does the same for cancellation. The service's claim/resolve path owns broadcast and finality. See `src/livekit/realtime-tools/create-realtime-tools.ts` (`decideTransfer`) and `src/conversations/service.ts` (`resolveDecision`, `runFinancialTransfer`).
- Tool descriptions and the English-only prompt request an explicit “yes”, but the `confirm_transfer` server callback does not receive or verify the user's transcript. `createAgentSession` creates an `AgentSession`; `worker.ts` starts that session and only registers room-binding and interrupt RPCs. `RoomConversation` has an exact phrase classifier for transcript decisions, but `worker.ts` does not connect it to `AgentSession.UserInputTranscribed`. Therefore prompt adherence alone is not server-side authorization. See `src/livekit/create-agent-session.ts`, `src/livekit/worker.ts`, `src/livekit/room-conversation.ts`, and `src/livekit/resolution-phrases.ts`.
- The LiveKit Agents dependency exposes `AgentSessionEventTypes.UserInputTranscribed`, including `transcript`, `isFinal`, `itemId`, and `createdAt`; realtime session dispatch emits this event before exposing it to application listeners. Installed package evidence: `node_modules/@livekit/agents/src/voice/events.ts` and `remote_session.ts`. Slice 4 can bind explicit confirmation evidence to final user transcripts. Ordering against tool callbacks still needs a deterministic test and must fail closed if evidence has not arrived.
- Solana devnet provider preview returns exact recipient, native SOL and an RPC-derived fee; broadcasting uses the bound user's Privy signer and finality is tracked through the provider. See `src/wallet/solana-devnet-provider.ts` (`previewTransfer`, `broadcastTransfer`, `waitForFinality`). Provider input validates base58, self-send, precision, and the network, but voice service recipient resolution is currently EVM-only: `src/conversations/service.ts` rejects contacts using `isValidEvmAddress`, and `src/memory/address.ts`, `src/memory/repository.ts`, and `src/memory/contacts-repository.ts` only admit EVM addresses.
- The transfer-policy functions are also EVM-only: `src/agent/definition.ts` validates allowed recipients with `isValidEvmAddress`; `src/agent/wallet-agent.ts` duplicates this live gate. Solana limits should remain lamports in policy/storage and render in SOL, honoring the Slice 2 cap of 10,000,000 lamports. Do not add an oracle.
- Existing voice tests exercise strict tool schema, room transcript resolution, preview races, cancellation, and a fake worker. Relevant files: `tests/unit/realtime-tool-binding.test.ts`, `tests/unit/livekit/room-conversation.test.ts`, `tests/integration/livekit-native-transfer.e2e.test.ts`, `tests/integration/voice-touch-decision-race.test.ts`, and `tests/integration/livekit-worker-fake.e2e.test.ts`. Current configured eval command is `npm run eval`.

## Design implication

Keep model-facing transfer tools as preview/decision adapters. Add a per-session, one-use authorization gate populated only by a final transcript matching the existing exact confirmation phrases after the current preview exists; reject model tool calls without that evidence and consume evidence atomically with the persisted preview decision. Cancellation should also require a final exact cancellation phrase. Extend versioned contacts to carry a chain/network discriminator and validate Solana addresses at write and use time, so voice still selects a contact ID and never supplies a free-form address. Return structured recipient display name and exact estimated fee to the model, but never the raw recipient address. Treat missing transcript evidence, stale preview, ambiguous recipient, invalid address, changed contact version, over-cap amount, and provider uncertainty as fail-closed results.


## Decisions resolved from research

- Use a saved, versioned, named Solana contact; raw-address voice input is out. Chain/network discriminator is explicit for Solana and backward-compatible for legacy EVM contacts.
- Narrate exact amount, saved contact name, token/network, and provider estimated fee; never read a raw address to the model. Existing EVM narration remains unchanged.
- The 0.01 SOL / 10,000,000-lamport ceiling is specific to delegated grants (Slice 2). Uncovered live voice transfers follow exact decimal-to-lamport validation and the configured `WDK_MAX_TRANSFER_AMOUNT`, with no oracle.
- Spoken confirmation must await the financial task's terminal result just as the realtime tool path does. Preserve the existing canonical claim and audit state; do not introduce a second transaction path.
- Missing Solana `previewId` must fail closed instead of generating `sol-${now()}`. Confirmed Solana projections must use the existing network-aware explorer URL helper.
- The existing exact phrase classifier should explicitly accept standalone localized `yes`, `sí`, and `si`, matching the current realtime tool instruction; cancellation remains distinct.

The research agent did not execute tests and only read the frontend implementation shallowly; implementation and verification tasks below include focused coverage of the contact form, projection, and fake-worker E2E.
